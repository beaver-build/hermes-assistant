# 任务修改的边界场景

停止条件不变：每个受影响任务一次写入 + 一次按 ID 回读。API 细节在 `dida365-api.md`。

## 编号批量操作

用户基于上一份编号清单说"1、5 完成，2 明天中午，8 下周六"：

1. 冻结**用户最后看到的**编号表，编号 → 当时的任务 ID；中间发生过写入但没展示新表的，仍以最后可见表为准。
2. `date` 读一次，整条消息的相对日期一次解析。
3. 逐项语义：
   - `done` / `OK` → 完成该任务；父任务显式 done 时即使 checklist 有陈旧细节也完成父任务。
   - `取消` → 删除，用精确标题搜索 + 日期/项目列表核验已不在。
   - 只改日期 → 保留原有钟点、时长、提醒；用户说"全天/一天"才改全天。原本无时段、用户也没给 → 按整段语义或问一次。"中午"落 12:00 并在确认里写明。
   - 改名 / 扩大范围 → 原地改标题、备注、checklist；范围变大时保留仍属新范围的未完成子项。
   - 旧平台 → 新平台 → 权威替换；唯一匹配的任务已完成且是历史时，创建一条无日期后继，不改写历史。
   - "其他不变" → 其余任务一字不动。
4. 混合操作并行执行；回读全部受影响任务；按"已完成 → 今天剩余 → 明天 → 后续 → 长期"回复。
5. 编号指向一条标题看不懂的提醒时，先说明它的创建上下文，再问完成还是删除。

## 部分完成与 checklist

- 一个任务含两个动作（"A 和 B"）只完成了其中一个 → 父任务保持未完成，标题改为剩余动作，备注记录已完成部分。
- 用户只提到某个子项 → 只更新该子项；子项完成不等于父任务完成。
- 补充进度、纠正范围、新增待确认项 → 更新原父任务，提交完整条目集；"考虑、可能、待确认"写进备注并新增未完成项。

## 进度汇报对账

一条消息同时含完成、进行中、阻塞、延期、方案替换、取消、下一步时，整条视为对现有任务的状态对账，逐主题原地修正：

| 措辞 | 处理 |
|---|---|
| 已完成 / 已跑通 / 已反馈 / 已拿到 | 完成对应里程碑或父任务 |
| 正在做 / 推进中 / 等待验证 / 待测试 | 父任务保持开放；`待测试`是开放跟进，用户没排进明天就留无日期 |
| 受 X 阻塞，延期到 Y | 保留阻塞原因，移动原任务 |
| 方案改了 / 去掉 X 改用 Y | 权威替换：标题、备注、checklist 里旧方案全部清掉；只负责"做选择"的任务完成，实施动作留在实施主任务 |
| 下一步 | 保留为开放行动 |

典型：“版本 0.0.1 已跑通，下一步产品化” → 版本里程碑完成、产品化开放、父任务开放；“数据库从 A 改成 B，正在适配” → A 移除、B 选型完成、B 适配开放；“修复完成，等线上验证” → 修复完成、验证开放。

父任务完成顺序：更新标题、备注、全部子项 → `complete_task` → 回读 `status`、`completedTime`。

## 文档作为里程碑证据

活跃任务之后紧接着来了文件：先看内容；只提取持久元数据（标题、范围、版本/基线、条目数、状态类别、负责人/依赖）；更新现有任务；只勾选文件证明的里程碑（如"初稿已收到"）；后续的适配、评审、补缺、验证、交付保持开放，并写明责任顺序。备注存摘要，全文留在文件里。

## 重复任务与目标

- 明确说"结束了" → 结束整组重复（api 文件流程）。
- "今天试过了" → 只完成当前尝试，重复系列保留。
- 目标已达成且存在多个等价任务 → 停止重复主任务、完成过时的一次性任务，无关后续不动。
- 提醒型重复 → 保留重复和提醒，只完成当前实例。

## 时间粒度

- 宽泛上午/下午预约：保留整段语义，明确实际钟点未知；"提前提醒"没给提前量就问一次；提醒时间不写成预约时间。
- 全天改定时：按意图重设合法的定时提醒并回读。
- 时段词 + 明确钟点：钟点优先，"中午 2:15" = 14:15，上下文保留在标题或备注。
- 模糊顺延（"推到下周"）：把日期真的移过去——"下周内完成"= 周一至周五的多日全天区间；回读确认旧日期的日程里已不再出现。
- 依赖只给顺序："X 完成后再做 Y" 保持无钟点；"他可能先发系统"保留"可能"，也别复制下游任务。

## 归类

- 想法追加了期限（"记录到这个月底"）→ 同一任务升级为待办：保留记录时间和原文，标题改为行动导向，加日期，需要时 `move_task` 到普通清单。
- 明确要求"记录到长期事项"且给了成果目标 → 无日期待办。
- 只有主题、无承诺无时间 → 「想法」，备注注明范围和时间未定。
- 责任转移给别人 → 原任务改为"跟进/等待某人"。
- 用户说两条任务相关 → 双方备注互加一句关联，日程、范围、提醒、状态各自独立。
- 同一事项同时有点时提醒和执行任务、用户要求合并 → 选信息更全的为规范任务，迁移提醒/已完成子项/进度/截止，已完成部分用子项表示，删除或完成重复项，回读。

## 截图与外部规则

- 截图里的行程：只记可见事实（日期、出发时间、班次、路线、乘客）；多日行程用总括任务 + 有具体出发时间的单独定时项。
- 提醒依赖外部规则（如某机构的预约开放时间）：先查官方来源；只有旧的或二手来源时标"待核实"，提醒时间选在最有依据的时间点之前，证据和提示写进备注。

## 回复

已完成 / 进行中·待验证 / 延期（绝对日期 + 原因）/ 方案替换，一行一项。
