# 自动化：cron 的创建与约定

## 通用要求

- cron 在新会话运行，prompt 必须自包含：时区、状态判定、过滤条件、写入方式、验证步骤、输出格式。
- 创建前先列现有任务，按名称、cron 表达式、投递目标去重；已有同等任务就更新。
- 投递到用户当前对话（origin）；创建后核对启用状态、表达式、下一次运行时间、投递目标。
- 输出适合聊天窗口阅读：先结论后细节，任务 ID 和调度元数据留在日志里。

约定三项（按名称查 cronjob 列表即可，时间由用户自定）：提醒型任务自动完成当天实例、未完成事项每日自动顺延、每日行程提醒。

## 次日顺延

状态判定：只有用户明确说完成/结束或服务端已完成才算结束；"推进中、已拿到素材、等待确认、需要增加功能"都是开放；已放弃不顺延。

1. `date` 定"今天""昨天"。
2. 查昨天及更早仍 `status=0` 的有日期任务；近期已知任务按 ID 回读补漏。
3. 只移动执行区间已在昨天或更早结束的任务。
4. 排除：无日期、重复任务、提醒型事项、已完成/已放弃、`dueDate` 仍在今天或未来的跨日任务。
5. 原地更新同一 ID：单日定时任务平移 start/due 保留钟点和时长；全天任务移到今天全天；checklist 提交完整条目集保留状态和排序；备注里的"今日/明日/旧日期"同步改掉。
6. 按 ID 回读，再用当天范围查询整体核验。无需移动时报告"今天没有需要自动顺延的事项"。

## 日程简报

- 顺延先跑、简报后跑；简报仍独立查询，发现逾期开放事项如实列出，本任务只读。
- 覆盖完整日期窗口（见 `agenda-queries.md` 完整性清单）；重点任务按已知 ID 回读。
- 按用户明确的优先级 / `sortOrder` 展示，未编号的按时间。
- 保留"推进中、等待反馈、需要增加功能"等状态，不当作完成。
- 输出：`今天（M月D日，周X）` → `今日重点` → `固定时间 / 全天持续事项` → `已完成`（有内容才列）。无日程写"今天暂无日程安排"。

## 提醒型自动完成

按 ID 回读提醒型重复任务；当前实例日期是今天或更早且未完成 → 只完成当前实例；回读直到主任务推进到未来日期；`repeatFlag` 保持不动；其他任务不碰；只输出一条简短执行日志。
