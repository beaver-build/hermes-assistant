# 日程查询：窄时段、全部日程、已完成汇总

范围接口只给候选集（见 `dida365-api.md`）；完整性和过滤在本地完成。

## 完整性清单

"今天的日程"必须覆盖：定时、全天、跨期且今天仍有效、逾期未完成、重复任务的当天实例；已完成只在用户要求时列出。

补齐候选集的三条路：
1. 日期范围接口一次；
2. `search_task` 找未完成的重复主任务 → `get_task_by_id` 取 `status / startDate / timeZone / repeatFlag / 结束条件 / 例外日期` → 本地展开区间内实例；
3. 本会话刚创建、改期或被编号引用的任务按 ID 回读。

按任务 ID + 实例日期去重，本地时区归一后升序排列。

## 窄时段（"下午的日程""今晚"）

1. 归一化每个候选的起止到本地时区。
2. 只保留与请求窗口有交集的定时任务；上午任务 12:00 结束，接口返回了也归上午。
3. 逾期未完成的上午任务只在用户问"今天还没做完什么"时列出。
4. 覆盖该时段的全天/跨期事项单列"全天进行中"。

## 全部日程 / 重排前总览

触发："今天之后所有日程""我要重排一下""未来安排都给我看"。

1. 同一条消息里要求新记的事项先创建、回读，只写那一条。
2. `date` 定边界；查今天起未完成的有日期任务：定时、全天、跨期、远期固定。
3. 补重复主任务和已知 ID（第 2、3 条路）。远期节日、续费、生日也要覆盖——查 14 天就称"全部"是错的。
4. 展示后**等用户逐项指定**移动、取消、完成；总览阶段只读。

展示结构：
- **今天**：已过时间未完成 / 全天 / 接下来
- **明天和近一周**：按日期列时间；同日起止的出差单列
- **阶段性重复**："每天 20:00，8月10—17日"，同一时刻的两组明确标出
- **长期重复**："每天 08:00""每月 26 日"，附停止条件
- **远期固定**：按月份列
- **跨期**：起止日 + 截止日，一行

精简模式（用户说"简单点"或未要求展开）：日期、时间、标题，一行一项；同一时刻合并；跨期与提醒型各一行。原标题含糊或像占位符时原样展示并标"原任务标题"。

## 今日已完成汇总

合并三个来源后去重：`list_completed_tasks_by_date` 的父任务；打开的 CHECKLIST 父任务里今天勾选的子项；用户明确报告的阶段成果。区分"整项完成"和"阶段进展"；提醒型事项单独标注。

## 特殊项目的归类

- 聚合提醒容器（把多件事打包成一条提醒的任务）：从可执行清单排除，需要时单列"提醒记录"；备注里的真实任务与已单独存在的任务去重。
- 委派出去的工作：显示为"跟进/等待某人"。
- 提醒型重复任务：标为提醒，不列入待勾选。
- 无日期普通待办：用户明确要"所有待办"时才混入日程。

## 冲突

只报告已确认的同起始时间；没有时长信息时只列出，不推断重叠。
